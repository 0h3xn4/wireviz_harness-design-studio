This is **version 2.1.0**, a minor release. **One device connector can now carry several interfaces**, and on a pinout that names its ports, each interface gets the pins of one port. **There is no format change:** a port is part of the signal name of a pin (`RS422_2_TX+`), not a new field. 2.1.0 writes format 2 as 2.0.1 does, and format 2 stays frozen. If you come from 2.0.1 or 2.0.0, install 2.1.0 over it; your projects need no step. If you come from 1.17.1 or older, upgrade each project once to format 2, as the notes of 2.0.0 say. The guide is *Upgrade a project to format 2* in the user manual (`docs/user-manual/upgrade-a-project.md`).

### From 2.0.1 to 2.1.0

- **Install over 2.0.1.** Install the `.deb` or the Windows setup program the same way as before. Unpack the `.tar.gz` into a new folder and run `./install.sh` there, or unpack the `.zip` into a new folder.
- **Update the whole team at the same time.** 2.0.x does not read port names. If someone runs Generate with 2.0.x on a project that uses them, those interfaces fail with *no free pin named TX+*, and their draft harnesses are dropped. Released harnesses and locked pins stay, and the next Generate with 2.1.0 makes the drafts again. Each version also writes its number into `project.json` and the generation record, so a team that mixes them changes these files on every save.
- **Projects stay as they are.** A project that generates at 2.0.1 generates the same at 2.1.0. Every written file is the same, apart from the version stamp and the model hash that includes it.
- **Export once if you use `verify --outputs`.** It compares the files in `outputs/` with the version that runs, so outputs written by 2.0.1 fail it until you export them with 2.1.0.

### The main changes

- **Several interfaces on one connector.** 2.0.1 allowed one interface per device connector. Now a connector that already carries interfaces takes another one while it has room. The tool decides the room with a dry run of Generate's own pin assignment, so the editor and Generate cannot disagree.
- **Ports on a fixed pinout.** A pin named `RS422_2_TX+` (also `RS422_2.TX+`, `TX+-RS422_2` and the like) is the signal TX+ of the port RS422_2. Generate gives each interface all the pins of one complete port and never mixes two ports. The explanation of a pin names its port.
- **A worked example: three RS-422 links on one connector.** An on-board computer OBC1 talks to three star trackers through its one connector J1. Import the pinout of OBC1 with a **Port** column (`RS422_1`, `RS422_2`, `RS422_3`); the import writes the port into each signal name. Connect OBC1 to each star tracker in Guided mode: the first link takes J1, the only free connector, and the tool takes J1 again for the second and the third, because it has a free complete port. **Generate** gives IF-001 the port RS422_1, IF-002 RS422_2 and IF-003 RS422_3. To put a link on another port, use **Choose port…** in the Inspector. The user manual has the whole example (*Generate harnesses*, `docs/user-manual/generate-harnesses.md`).
- **The Inspector shows the port of each end**, for example *Port RS422_2 (pins 5-8), chosen by Generate*. **Choose port…** lists the complete ports of the connector, says why a port cannot be taken, and locks the pins of the chosen port to the interface in one undo step. The next Generate keeps the interface on that port.
- **A full connector is refused with the reason.** In Expert mode the diagram greys out a full connector, and a click says why: *J01 cannot take another RS-422: its RS-422 ports RS422_1, RS422_2 are used by IF-010, IF-011*, or *… too few free pins for TX+, TX- (2 free, 4 needed)*. The Inspector lists it as *J1: Full* and does not offer it.
- **The Port column of the Devices tab** shows the complete port each pin is in and the interface on it, for example *RS422_2 (IF-012)*. It is worked out from the pin names; it is not stored and not exported. **Assign…** has a **Port** list.
- **Guided mode chooses in two steps.** First a free connector that carries the type, exactly as before, so every project and every example chooses the same connectors. Only when none is free does it take a connector with a fixed pinout that has a free complete port of the type.
- **`import-pinout` and the import wizard read a Port column** (*Port*, *Port name* or *Port ID*). The preview lists the ports of each connector and warns about a port that misses a signal or has one twice.
- **New messages.** The warning `pin_port_unknown` says when the pins of several ports carry the same bare names (`TX+` three times) and the tool cannot tell which pins form one port. The verifier reports `port_mixed` when one interface uses the pins of two ports. The inline note CD-K9 under the pin table says what is wrong with a port.

### Known limits

- **Two plugs on one connector until 2.3.0.** Interfaces from one connector to different far connectors get one harness each, so the connector gets one plug per harness. Generate warns `box_connector_shared`, and the design rule `model-inconsistent` reports the plugs. To get one harness with one plug, set `segmentation.mode` to `per_zone_pair` and put the far devices in one zone. A harness that branches is planned for 2.3.0.
- **Guided mode does not warn about the second plug.** When Guided mode puts an interface on a shared connector, the message after connecting does not say that the connector gets a second plug. Expert mode says it, and so do Generate and the design rules.
- **Ports are read from the pin names only.** A name that reads in two ways, a port that misses a signal and a port with two pins for one signal are refused or reported, never guessed. The owner can still choose a field `Pin.port` in a later format instead.
- **The prototype is simpler.** The clickable prototype (`prototype/`) counts the free pins of the connector's part; it does not read ports.
- **Nobody has looked at the screens on a real display**, and the Windows packages were built and tested on GitHub's runners only, not on a real Windows computer. The Windows packages have no Windows code-signing certificate, so SmartScreen shows *Windows protected your PC*: **More info**, then **Run anyway**.
- **No compliance and no sign-off is claimed.** The configuration values are placeholders until your project supplies them.
