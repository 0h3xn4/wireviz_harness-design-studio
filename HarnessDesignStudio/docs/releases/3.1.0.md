This is **version 3.1.0**, a minor release of 3.0.1. It adds **the search boxes of the harness plan**: type a text into the box over Function or over Shielding, and every cell of that column that contains it shows in red bold. **There is no format change:** 3.1.0 writes format 3 as 3.0.1 does, and format 3 stays frozen. If you come from 3.0.x, install 3.1.0 over it; your projects need no step. If you come from 2.x, read the notes of 3.0.0 first: each project is upgraded once to format 3. If you come from 1.17.1 or older, the same upgrade takes a project through format 2 to format 3 in one step. The guide is *Upgrade a project* in the user manual (`docs/user-manual/upgrade-a-project.md`).

### From 3.0.x to 3.1.0

- **Install over 3.0.x.** Install the `.deb` or the Windows setup program the same way as before. Unpack the `.tar.gz` into a new folder and run `./install.sh` there, or unpack the `.zip` into a new folder.
- **Update the whole team at the same time.** 3.0.x and 3.1.0 each write their version into `project.json` and the generation record. A team that mixes them changes these files on every save.
- **Projects stay as they are.** The harness plans get the search boxes; every other written file has the same content, apart from the version stamp and the model hash that includes it. The command line and the scripting interface are unchanged.
- **Export once if you use `verify --outputs`.** It compares the files in `outputs/` with the version that runs, so outputs written by 3.0.x fail it until you export them with 3.1.0. A plan written by 3.0.x has no search boxes, and 3.1.0 reports it until it is written again.

### The search boxes of the harness plan

- **Why.** The users' template has two search boxes on the harness sheet, and 3.0.0 left them out because they need `SEARCH` and `ISNUMBER`, which were not in the closed list of functions of the plan. The owner allowed both on 2026-11-19 (decision D-250).
- **What you see.** Above the table, `I2:I3` (over Function) and `M2:M3` (over Shielding) hold *Column Search String* and `#`. Type a text into `I3` or `M3` in place of `#`: every Function or Shielding cell of the rows of the near connectors that contains the text, without regard to case, shows in red bold. `tx` marks `RS422_TX+` and `TX`; an empty box marks nothing. The Notes sheet says how to search.
- **The text is read as typed.** Every `.ods` the tool writes now turns regular expressions and wildcards off, so LibreOffice finds `TX+` as it is typed. `verify --outputs` reports a plan without that setting.
- **Still a closed list.** `SEARCH` and `ISNUMBER` are allowed in a conditional format only; a cell formula with either is still refused by the writer and by `verify --outputs`. See [Export the harness plans](../user-manual/export-the-harness-plans.md).

### Known limits

- **Excel reads wildcards.** Excel ignores the setting and reads `*`, `?` and `~` in a search text as wildcards; LibreOffice reads the text as typed.
- **Search in a copy.** A plan saved with a typed search text is a changed plan, and `verify --outputs` reports it. Search in a copy, or close the plan without saving.
- **The limits of 3.0.1 stand.** The tool never reads a harness plan back, and an export overwrites it; Generate makes no splice; the row layout of a connector is not in format 3 (planned as format 4, the next planned release, 4.0.0).
- **Nobody has looked at the search boxes on a real display.** They were checked by the tests, and against LibreOffice where it is installed. Nobody has looked at the screens of 3.0.0 on a real display either, and the Windows packages were built and tested on GitHub's runners only, not on a real Windows computer. The Windows packages have no Windows code-signing certificate, so SmartScreen shows *Windows protected your PC*: **More info**, then **Run anyway**.
- **No compliance and no sign-off is claimed.** The configuration values are placeholders until your project supplies them.
