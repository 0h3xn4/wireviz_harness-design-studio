This is **version 2.1.1**, a patch release of 2.1.0. It fixes three things that the end-to-end test of 2.1.0 found. **There is no format change:** 2.1.1 writes format 2 as 2.1.0 does, and format 2 stays frozen. If you come from 2.1.0, install 2.1.1 over it; your projects need no step. If you come from 2.0.x, read the notes of 2.1.0 first: 2.0.x does not read port names, so update the whole team at the same time. If you come from 1.17.1 or older, upgrade each project once to format 2, as the notes of 2.0.0 say. The guide is *Upgrade a project to format 2* in the user manual (`docs/user-manual/upgrade-a-project.md`).

### From 2.1.0 to 2.1.1

- **Install over 2.1.0.** Install the `.deb` or the Windows setup program the same way as before. Unpack the `.tar.gz` into a new folder and run `./install.sh` there, or unpack the `.zip` into a new folder.
- **Update the whole team at the same time.** 2.1.0 and 2.1.1 each write their version into `project.json` and the generation record. A team that mixes them changes these files on every save.
- **Projects stay as they are.** Every written file has the same content, apart from the version stamp and the model hash that includes it, and apart from the new advice on more than one plug on a device connector (below).
- **Waive one finding again.** The text of a design rule finding is part of its ID. A waiver of `model-inconsistent` on a connector whose plugs all belong to harnesses that Generate makes, made with 2.1.0, shows as stale in 2.1.1. Read the new advice and waive it again if it still applies.
- **The column widths of the pin table are set back once.** If you made columns of the Devices tab's pin table wider or narrower, set them again.
- **Export once if you use `verify --outputs`.** It compares the files in `outputs/` with the version that runs, so outputs written by 2.1.0 fail it until you export them with 2.1.1.

### The fixes

- **`explain` of a connector with several interfaces names each interface once.** Before, it repeated the step *Connectors of OBC1 that carry rs422 …* once per interface, without naming one. Now the interfaces with the same choice share one step that names them. The equation names both tiers of the Guided choice: a free connector first, then a connector with a fixed pinout that has a free complete port.
- **The advice on more than one cable plug says what you can do today.** For harnesses that Generate makes, the warning `box_connector_shared` and the finding `model-inconsistent` now say: put the far devices in one zone and set `segmentation.mode` to `per_zone_pair`, or use different connectors, or accept the second plug until a harness can branch (planned for 2.3.0). For a harness drawn by hand or released, the advice stays as in 2.1.0.
- **The *Port* column of the Devices tab follows *Signal*.** At 1440 × 900 it was out of view until you scrolled sideways. It is now next to the signal it is read from, and wide enough for *RS422_1 (IF-001)*.

### Known limits

- **The limits of 2.1.0 stand.** Until a harness can branch (2.3.0), interfaces from one connector to different far connectors get one plug each on it. In Guided mode the message after connecting does not say that a shared connector gets a second plug. The prototype counts the pins of the part, not the ports.
- **Nobody has looked at the screens on a real display**, and the Windows packages were built and tested on GitHub's runners only, not on a real Windows computer. The Windows packages have no Windows code-signing certificate, so SmartScreen shows *Windows protected your PC*: **More info**, then **Run anyway**.
- **No compliance and no sign-off is claimed.** The configuration values are placeholders until your project supplies them.
