This is **version 2.4.0**, a minor release. **A new project makes one harness that branches**: it starts with `segmentation.mode` = `per_connector_group`, so a device connector that carries interfaces to several devices gets one plug, and Generate splits the harness at a branch point. Existing projects keep their mode. 2.4.0 also puts the revisions after Z in order. **There is no format change:** 2.4.0 writes format 2 as 2.3.1 does, and format 2 stays frozen. If you come from 2.3.x, install 2.4.0 over it; your projects need no step. If you come from 2.2.x or older, read the notes of 2.3.0 first. If you come from 1.17.1 or older, upgrade each project once to format 2, as the notes of 2.0.0 say. The guide is *Upgrade a project to format 2* in the user manual (`docs/user-manual/upgrade-a-project.md`).

### From 2.3.x to 2.4.0

- **Install over 2.3.x.** Install the `.deb` or the Windows setup program the same way as before. Unpack the `.tar.gz` into a new folder and run `./install.sh` there, or unpack the `.zip` into a new folder.
- **Projects stay as they are.** A project keeps the mode it names, and nothing switches it. A project that generates at 2.3.1 generates the same at 2.4.0; every written file has the same content, apart from the version stamp and the model hash that includes it.
- **Update the whole team at the same time,** before anyone makes a new project with 2.4.0. Each version writes its number into `project.json` and the generation record. A 2.3.x tool knows `per_connector_group` and groups a new project of 2.4.0 the same way. A 2.2, 2.1 or 2.0 tool reads the mode as not known, uses `per_connector_pair` and removes a joined draft on its next Generate.
- **Scripts that make projects.** `new FOLDER` and `create_project` of the scripting interface now give `per_connector_group`. A script or a test that counts on one harness per pair of connectors sets the mode first: `harness-design-studio settings FOLDER --set segmentation.mode="per_connector_pair"`.
- **Comments in the config files.** The description of `segmentation.mode` now says what a new project starts in. If your config files carry the comments `_about` (`settings DIR --annotate`), `validate` and `config` warn `config_about_stale` for it until you run `settings DIR --annotate` again.
- **Export once if you use `verify --outputs`.** It compares the files in `outputs/` with the version that runs, so outputs written by 2.3.x fail it until you export them with 2.4.0.

### The main changes

- **A new project starts in `per_connector_group`.** `new FOLDER` (the blank project), **File > New project** with the empty project, `create_project` and the empty project of the usability kit. A 21-pin Micro-D that carries RS-422, RS-485 and CAN to three devices gets one harness with one plug on it, one branch point and four segments, where `per_connector_pair` gave three cables with three plugs on it. A project with no shared device connector gets the same harnesses in both modes.
- **An existing project is offered the change once.** In a project in `per_connector_pair` whose device connector has the plugs of several harnesses, the editor says so once after **Generate**, with the button **Make one harness that branches**: it chooses `per_connector_group` as *Settings > Project* does, in one undo step, and offers **Generate again**. Close the notice to keep `per_connector_pair`; the editor remembers the answer for the project on this computer, not in the project's files.
- **The examples keep their mode,** so their written files are unchanged: `first-steps`, `minimal-satellite` and `small-satellite` stay `per_connector_pair`, `flatsat` stays `per_zone_pair`. A file that names no mode is still read as `per_connector_pair`.
- **The revisions after Z are in order.** The top bar showed the range of the revisions as `AA-Z` when one harness was at revision Z and another at AA; it now shows `Z-AA`, the order the list of baselines already used.
- **The command line and the scripting interface are unchanged** (`harness_design_studio.api`, `API_VERSION` 1).

### Known limits

- **The notice is in the editor only,** once for each project on each computer. The command line keeps the warning `box_connector_shared` in `per_connector_pair`.
- **The limits of 2.3.0 stand.** Splices are not in it (planned for 3.0.0, with format 3), so a new leg takes only the free pins of a plug. Joining is in `per_connector_group` only, and not for connectors wired in a ring, chains kept apart or a released harness. The routing tree, the legs and the join are edited in the app only.
- **Nobody has looked at the notice or the New project window on a real display.** They were tested offscreen. The Windows packages were built and tested on GitHub's runners only, not on a real Windows computer. The Windows packages have no Windows code-signing certificate, so SmartScreen shows *Windows protected your PC*: **More info**, then **Run anyway**.
- **No compliance and no sign-off is claimed.** The configuration values are placeholders until your project supplies them.
