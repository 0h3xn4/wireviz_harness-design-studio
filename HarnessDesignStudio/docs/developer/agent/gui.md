# The editor (GUI): notes for agents

These sections were moved word for word from [`CLAUDE.md`](../../../CLAUDE.md) on 2026-10-29 (decision D-182); only this introduction is new. Read them when you work in `src/harness_design_studio/gui/` (the window, the panels, the roles, the Next step page, the Systems engineer path).

## GUI layout (M2, rebuilt in October 2026)
Window (`gui/main_window.py`): the navigation rail (Next step, Home, Model, Checks, Drawings, Outputs, As-built, Review, Versions, Settings; the area's key stays `revisions`; `gui/areas.py` maps every main tab to an area, `MainWindow.set_area` and `go_to` open them, the six main tabs stay in `main_tabs` and each area shows its own with `SlotTabs.set_filter`), the one-row top bar and banners, the open area (Home, Settings and, since S9 and 4.3.0, As-built and Review are pages; the other areas are the tabs Diagram / Harness / Lists / Checks / Releases / Devices, Ctrl+1 to 6), the project tree and the Interfaces tab (the editable interface table, Ctrl+Shift+T) on the left, the inspector (Inspector, Why, Problems with the to-do lines) on the right, the Problems panel (a bottom dock, closed until asked for, Ctrl+Shift+M) and the status bar with the job indicator. The Next step area (`gui/next_page.py`, a page like Home) shows the one next step chosen by the pure `gui/next_step.py`; the setting `ui/role` (`systems` or `electrical`; View > Role and Settings; D-176 replaced the Simple/Full workspaces of D-171) decides whether a project opens on it and what is on screen (a settings file with no stored value asks once, *Who are you working as?*, as a section of Home (`HomePage.show_role_question`, `MainWindow.choose_role_flow`), unless the hook `roles.FIRST_RUN_ROLE` is set; one with values and no role is an Electrical / AIT engineer, a stored `ui/workspace` of 1.7.0 carries over). For the Systems engineer (the old Simple, stage S2) `_apply_role` closes the docks, turns the minimap, legend, status counts and problem notices off, reduces the tool row to Select/Connect/Add device/More and leaves Home, Drawings and Outputs out of the rail (`areas.SYSTEMS_HIDDEN`; the rail lists the area that is open); the layout is stored per role (`role_key`: `ui/simple/...`, `layout/<hash>/simple/...` for the Systems engineer, the old plain keys for the Electrical / AIT engineer); the Show panels action opens and closes the tree and inspector together. **Quick mode** (`ui/quick`, off by default; `MainWindow.quick_on`, `_apply_quick`, called at the end of `_apply_role` and on a toggle) is a view on top of any role, stored apart from the role's layout memory: `areas.hidden_in(role, quick=True)` lists only Home, Model and Settings on the rail, `TopBar.set_quick` shows **Export diagram** in place of Generate, Check, Release, Export, the hash, the version and the chip (the fold in `_fit` / `_set_level` keeps working), `problem_notices_on()` is forced False, the status bar's job indicator does not show the automatic check (`_update_jobs`: only while `_check_asked` in Quick mode) and the tree hides its pending chips (`ProjectTree.set_quick`), there is no first-start question, a project opens on the diagram (`_open_for_role`), Connect (`link_flow` -> `quick_link_flow`, `core.links.plan_quick_link`) makes the link with no window as one undo step and Add device (`QuickDeviceDialog`, `ctl.add_device_quick`) asks for a name only. It changes only what the window shows and asks, never a project file, the model hash or a written output (`tools.output_hashes --check` and `tools.numbers_snapshot --check` stay identical). **Export diagram** (`File > Export diagram…`, `gui/diagram_export.py`) writes the block diagram as SVG, PDF and PNG with no folder, harness or check; the PNG is painted with QPainter because the package has no QtSvg. There is no old bottom dock and no palette (retired in October 2026; the mapping of every old function to its new place is in `docs/ux-audit.md`, Build status, and for the shell in `docs/ui/UI_OVERHAUL_PLAN.md` section 4). The look and every decision are in `docs/DESIGN.md`; what was built for each audit issue is in `docs/ux-audit.md` ("Build status"). All files are in `gui/`:

- Rules: tables are `tables.TableView` (never `QTableWidget`), states are `states.StateChip` or `StateDelegate` (never colour alone; pending and not checked have a pattern), icons come from `icons.py` (the package has no QtSvg), no `setStyleSheet` outside `theme/`, no `#RRGGBB` literal, font family or font size outside `theme/` (use `theme.color()`, `theme.font()`, `theme.type()` and `theme.space()`; `tests/test_theme_scan.py` fails otherwise), every string in `strings.py`, every control an accessible name and a tooltip with its shortcut, validation inline (never a message box). A new view gets its data from the controller and from headless code in `core`, never by reading files itself. A layout value of the window (panels, minimap, legend, the open area) is stored under `self._wkey(key)` (`role_key` of `gui/roles.py`), so one role's layout never overwrites the other's (`tests/test_ui_role_layout.py`); what a new control does for the Systems engineer role is decided in `_apply_role`.
- Headless logic the views read, in `core` (tested without Qt): `core/drc/by_rule.py` (one result per rule: pass, fail, not checked, pending), `core/vcs/lockview.py` (what a release locks, why, which fields stay editable), `core/vcs/timeline.py` (change log rows, differences by kind), `core/configcheck.py` (`engineering_values`, `plan_set_value`, `plan_placeholder`), `core/usedby.py`, `core/why.py`, `core/describe.py` (captions, link tooltip, unit picture), `core/generation_status.py`. Edit logic is in `core/edit.py`, `core/devices.py` (custom devices down to each pin: connectors, pins, pasted rows, inline pin checks, `device_state`, the pin-set lock of the planners; see `docs/ux-custom-devices-audit.md`), `core/checks.py`, `core/imports.py`, `core/recovery.py`; add new editor features there first, with tests, and keep the GUI thin.
- Never name a widget attribute `palette` (it hides `QWidget.palette()`).
- Panels that are not visible refresh lazily (on show). Tests that read a tab's widgets must switch to that tab first (`tests/gui_helpers.py`: `show_problems`, `win.show_interfaces()`, `win.go_to(name)`; `add_unit` and `pick_connect_type` do what the retired Palette buttons did).
- Dialog hooks (`run_dialog`, `ask_folder`, `ask_text`, `ask_choice`, `ask_file`) exist so tests can drive the UI without blocking.
- Diagram drawing rules that need no Qt live in `core/routing.py` (edge a link leaves from, orthogonal trunk routing of all links, focus of a selection) and `core/describe.py` (link values, connector family from the part); the pictures are drawn in `gui/glyphs.py` and keyed in `gui/legend.py` — show meaning with pictures, not letters or raw text; `tests/test_gui_readability.py` checks them on the flatsat example. Unit room (`edit.unit_footprints`) is the taller of the guided and expert heights, so units never overlap in either mode; `tools/build_examples.py` arranges the examples with it. Pictures for `docs/FLATSAT_EXAMPLE.md`: `python -m tools.flatsat_screenshots`. **Device looks (REQ-GUI-20):** what a device looks like comes from its kind: `core/device_kinds.py` (no Qt, so the written diagram reads it too) is the one table, `KINDS` in priority order, that reads the kind from the name, then the ID letters, the subsystem and, last, `describe.unit_glyph` (the links), unless a person set the optional, sparse field `Unit.kind` by hand (REQ-GUI-24; it is written only when set, so a project without it keeps its bytes and its model hash; `device` forces the plain box; the Kind list of the inspector is `PropertiesPanel._kind_combo`, the edit is `edit.ops_update_unit(kind=...)`); `gui/device_kinds.py` re-exports it and holds the words (`sentence`); the pictograms and badge outlines are path data in `core/pictograms.py` (16 x 16 box), which `gui/device_looks.py` turns into `QPainterPath`s and `core/outputs/looks.py` into `Shape` items for the written block diagram (REQ-GUI-25; the colours are `device_kinds.ACCENTS`, the one table the `device.*` tokens are made from); `gui/device_looks.py` draws the badge (a shape by family, the accent of the token `device.<family>` filled, the ink `accent.text`), the band on the left edge, the tint of a box seen from far away, the inspector's line and the legend's badges. The canvas has three hooks and nothing else (`UnitItem.facts().looks`, `device_looks.paint_header` and `paint_overview`, the line `device_kinds.sentence` in the tooltip); the header is not tinted because the small muted text on it is 4.5:1 only on the plain header. A new kind: one `Kind` in `KINDS`, one function in `PICTOGRAMS`, a row in the table of `docs/user-manual/telling-devices-apart.md`, a test row in `tests/test_ui_device_looks.py`. A new family needs two tokens (light and dark) that pass `tests/test_tokens.py`.
- Keep edits under 100 ms at stress size: use the Delta, never rebuild the whole scene for a local change, and never call `update()`/`prepareGeometryChange()` on the lane (zone) items or the overview map for a local edit (they are as tall as the diagram; one such call repaints every item). `tests/test_gui_perf.py` guards this by counting dirty regions.

## Roles and the Next step page (1.7.0 D-171, roles D-176)
`gui/next_step.py` (no Qt: `next_step(NextInputs)` gives the one next step and the six step lines) and `gui/next_page.py` (`NextStepPage`: shows it and calls back; the window maps each key to an existing flow; the buttons *Library…* and *Show everything* show for the Systems engineer only). `gui/roles.py` (no Qt: `ROLES`, `SYSTEMS`, `ELECTRICAL`, `default_role`, `clean_role`, `role_key`, the hook `FIRST_RUN_ROLE`) and the question of the first start, *Who are you working as?*, a section of Home (`gui/pages.py`: `RoleChoice`, `HomePage.role_card`, `show_role_question`; the window `RoleDialog` was removed on 2026-11-17). `MainWindow._restore_role`, `_apply_role`, `set_role` (any choice answers the question), `choose_role_flow` (stores the answer and keeps the landing page), `_open_for_role`, `show_panels`, `show_everything` and `areas.SYSTEMS_HIDDEN` do the rest (see "GUI layout"). **Rules:** a role is a view, never a permission and never written into a project or the command line; nothing a role leaves out may become unreachable (menu, key, palette; `tests/test_ui_roles.py` checks it); the role is `act-role-systems` / `act-role-electrical` first, with the Settings row a view of them; the question of the first start is skipped when `roles.FIRST_RUN_ROLE` is set (`tests/conftest.py` sets `electrical`, so no test waits on it) and when the window was built with `first_run=False`; internal layout keys keep the word `simple` (`ui/simple/...`) so no saved layout is lost, and the code says role everywhere else. A stage S3 (plain words) was discarded by the owner and is not built; S4 (a blank project that asks one thing at a time) is not built. New texts go in `gui/strings.py`; tests: `tests/test_next_step.py`, `test_roles.py` (no Qt), `test_ui_next_page.py`, `test_ui_role_layout.py`, `test_ui_roles.py`. User page `docs/user-manual/choose-your-role.md`; pictures `docs/img/role-question.png`, `role-menu.png`, `systems-engineer.png`, `electrical-engineer.png` (`tools/tab_screenshots.py`, `_role_pictures`).
