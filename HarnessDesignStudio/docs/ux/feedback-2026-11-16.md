# Demo feedback of 2026-11-16

Two people saw a demo of Harness Design Studio 2.0.0 on 2026-11-16 and answered the same questions afterwards. This page records what they said, without their names, and maps each point to what the tool does today, what is missing and when it is planned. Quotes are their own words. It is the first feedback of people outside the project since 2.0.0; it is a demo, not a usability session ([`../usability/README.md`](../usability/README.md)), so nothing here is a measured result.

## What they said

**Participant 1 (systems engineer).**

- Hardest part: "a bit more clarity on the auto checks or auto linking between interfaces and how that works".
- Most useful: block diagrams with the units imported from KiCad; harness plans made easily from the systems engineering block diagram, which the electrical team then tailors and reviews.
- Missing: "Multi-point connections: one connector should be able to connect to many other interfaces"; "automatic linking of already predefined pin assignments, for when we import an interface with several RS422 IFs for example".
- Needs: Windows; export to PDF and potentially Excel.
- Concern: "we just need to figure out the AI created safety use topic".
- Will try it. A short session was enough. Next time: real examples with their own units, once the security question is clarified.

**Participant 2 (electrical engineer and AIT).**

- Hardest part: connector IDs and tags.
- Most useful: the automation of the connections (it saves time). The outputs they would use: the harness plans and the block diagram.
- Missing: "multiple connectors to single connectors"; libraries.
- Needs: PDF and spreadsheet.
- Concern: "fine as far as the company allows this tool".
- Will try it by making a couple of harness plans. Wish: "link to our repos: if I select a device, for example PCDU00, I should see the pinouts of its connectors".
- Next time: a real example.

## What the owner decided

On 2026-11-16 ([`../DECISIONS.md`](../DECISIONS.md)):

- **D-233:** CD-Q3 reopened, yes: the editor will allow several interfaces on one connector, with the automatic pin assignment of several interfaces of one type; 2.1.0. It supersedes the earlier answer in [`../ux-custom-devices-audit.md`](../ux-custom-devices-audit.md).
- **D-234:** CD-Q4 decided: reusable devices live as a folder of `NAME.device.json` files, which can be a Git repository and to which a project or a user points; 2.2.0.
- **D-235:** the order of the 2.x releases: 2.0.1 (M7b and the release bundle), then the documentation of this feedback, 2.1.0, 2.2.0, 2.3.0 ([`../ait/PLAN_2.0.md`, section 3.6](../ait/PLAN_2.0.md#36-order-after-the-feedback-of-2026-11-16)).
