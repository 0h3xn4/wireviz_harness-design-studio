## Commands (run from `HarnessDesignStudio/`)
- Setup (Python 3.14 or newer): `python3.14 -m venv .venv && . .venv/bin/activate && pip install -e ".[gui,dev]"` (Linux also needs libegl1 libgl1 libxkbcommon0 libxkbcommon-x11-0 libfontconfig1 libdbus-1-3 libxcb-cursor0 for Qt; the full list that CI and the `.deb` use is in `docs/INSTALL.md`, "If the app does not start")
- Test: `pytest` (Qt runs offscreen via tests/conftest.py); coverage: `pytest --cov` (90% gate on core, enforced). In parallel (pytest-xdist, D-148): `pytest -n auto -m "not perf"` (pull requests also leave out `-m slow`, the 42 tests of about 10 s or more; `master` and `tools.release_check` run them), then the tests with a wall-clock limit alone: `pytest -m perf` (they carry `@pytest.mark.perf`; `tests/test_parallel_safety.py` fails if one does not). CI runs both steps with `--cov`/`--cov-append`. Tests use `tmp_path` and never a fixed path, so workers do not share files.
- Lint/type: `ruff format . && ruff check . && mypy`
- CLI: `harness-design-studio --version | new FOLDER [--template NAME] | templates FOLDER | schema FOLDER | validate DIR | check DIR | migrate DIR [--dry-run] | merge-fix DIR | generate DIR | verify DIR | drc DIR | export DIR [--drawings] [--run-record] | export-data DIR --out FOLDER [--run-record] | verify DIR --outputs | review/release/revise/diff/log DIR HARNESS | compare OLD NEW | config DIR | settings DIR [--annotate] | explain DIR OBJECT | routing DIR HARNESS | workflow DIR | override/deviation/journal DIR | library DIR | import-parts/import-lengths/import-build-data/import-netlist/import-pinout/import-devices/import-subsystem DIR FILE | export-pinout/export-devices/export-subsystem | asbuilt DIR / import-asbuilt / export-asbuilt | imports DIR | libraries/add-device/update-device/save-device DIR … | extensions DIR [--all|--docs|--enable|--disable] | trust DIR [NAME] [--revoke|--yes] | import-plugin DIR NAME FILE` (`harness-design-studio COMMAND --help` for the options; `docs/CLI.md` is generated from the parser); GUI: `harness-design-studio-gui` (the source install takes only `--version`; the packaged editor, `packaging/gui_entry.py`, also takes `--selftest [--selftest-out FILE]` and `--check-system`); `harness` and `harness-gui` are kept as aliases
- GUI tests: `QT_QPA_PLATFORM=offscreen pytest tests/test_gui_journeys.py` (conftest sets it); the layout tests also run on Qt's real `xcb` (under `xvfb`) and `windows` platforms in `.github/workflows/harness-real-platform.yml` (not a required check; REQ-GUI-26, `docs/developer/setup-and-tests.md` section 6), and `tests/test_ui_four_actions.py` holds the quick path to `FOUR_ACTIONS_BUDGET` (REQ-GUI-27); timings: `python -m tools.bench_gui`; screenshots of the real editor: `python -m tools.gui_screenshots` (docs/ux/qt, 30 pictures, about a minute) and `python -m tools.flatsat_screenshots` (docs/img)

## Conventions
- `core` must not import `gui`, `cli` or any network module. Offline guarantee is tested.
- All model changes go through commands/transactions; GUI never mutates the model directly.
- Deterministic everywhere: sort by stable IDs, no timestamps in generated data, canonical JSON.
- Never invent standard values (derating, current ratings, mass). Use `PLACEHOLDER` config values and list them for the owner.
- No design data in logs. UI strings in one module.
- The screen says *device*, the files say *unit* (`Unit`, `units`, `logical/units/`, `unit_id`, and the finding texts that reach a written output file); the command line has `--device` and keeps `--unit`; the one exception is the connection list (`system/connections.csv` and `.xlsx`, new in 1.9), whose headings say *device* (owner decision); a wording change on screen must not change a generated file (`python -m tools.output_hashes --check docs/ui/OUTPUT_HASHES_BASELINE.json`). The one deliberate exception is 3.0.0 (D-242, Q23): *Revision* became *Version* in the files and on screen together, once, with format 3, and the baseline was made again for it.
- Every new dependency: record name, version, licence in `docs/DECISIONS.md`.
- Every new source file (`.py`, `.sh`, `.js`, `.html`, `.iss`, `.toml`) starts with the two SPDX lines (`SPDX-FileCopyrightText: 2026 0h3xn4`, `SPDX-License-Identifier: GPL-3.0-only`); other files are covered by `REUSE.toml`. Check: `reuse --root . lint` (CI job `reuse`).
- Legal texts (disclaimer, intended use, status, AI authorship, licence, non-affiliation, trademarks, privacy, output notice) are written only in `compliance/legal/texts.md` and copied word for word (D-210): change the source, run `python -m tools.gen_legal_texts`, then the copies; `tests/test_legal_texts.py` fails on drift. Do not write promise words about the tool or its results (`tests/test_promise_words.py`). Do not write "clean-room" (D-211).
- Tests first; every bug fix gets a regression test.
- End each session with: done, tested, next, UX targets met/open.
